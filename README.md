**Yari** is a Java framework built around two things:

- **Four distinct, fast and fault-tolerant parsers** — one each for **JavaScript, HTML, CSS and XML** — that produce a **unified, fully-located AST**. The HTML parser also parses the JavaScript and CSS embedded in a page (`<script>`, `<style>`, `onclick`, `style`…), so you can walk a whole document — markup, scripts and styles — in a single pass. The parsers are engineered for throughput: they handle large files and minified bundles quickly, in one linear pass. And they **never throw** — malformed input becomes an error node in the tree, so you always get a usable AST.
- **A powerful parser-combinator engine** — [`yari-parsec`](./yari-parsec/README.md), the same machinery the four parsers are built on. Use it to write your **own** fast, resilient parser for any language or DSL, with operator-precedence tables, automatic source-location tracking, and error recovery as a first-class primitive.

Every AST node carries an exact source location, comments are kept as first-class nodes, and the whole tree serializes to JSON out of the box — a solid building block for static analysis, tooling, and AI-driven code understanding.

## Modules

- **[yari-parsec](yari-parsec/README.md)** — Parser combinator library on which the entire framework is built. Compose small, well-typed `Parser<T>` values to scan characters, tokenize, build expressions with precedence/associativity, track source locations, and recover from errors.
- **[yari-core](yari-core/README.md)** — Common interfaces and abstractions shared by every module: the AST contract, source location system, and base utilities. *Depends on yari-parsec.*
- **[yari-xml-parser](yari-xml-parser/README.md)** — Fault-tolerant XML parser producing a typed AST. Supports simple and complex tags, self-closing tags, comments, CDATA, DOCTYPE, prolog, and namespaces. *Depends on yari-core.*
- **[yari-css-parser](yari-css-parser/README.md)** — Fault-tolerant CSS parser producing a typed AST. Supports complete stylesheets, at-rules, complex selectors (pseudo-classes, pseudo-elements, combinators, nth-patterns…) and property values. *Depends on yari-core.*
- **[yari-javascript-parser](yari-javascript-parser/README.md)** — Fault-tolerant JavaScript parser producing a typed AST. Supports functions, classes, ES6 modules (import/export), async/await, destructuring, template literals, generators, and more. *Depends on yari-core.*
- **[yari-html-parser](yari-html-parser/README.md)** — HTML parser that extends the XML parser and additionally processes embedded JavaScript and CSS (`<script>`, `<style>`, `onclick`, `style`…). Produces a unified AST where each sub-language is parsed into its own tree. *Depends on yari-xml-parser, yari-css-parser, yari-javascript-parser.*

## Why this framework

This framework was built to fill a gap: **fast, pure-Java parsers** capable of handling **complex, real-world web code** — not just textbook-clean inputs.

- **Real-world web inputs.** HTML pages in the wild rarely respect strict XML — unclosed tags, missing quotes, mixed casing, broken nesting. The HTML parser is designed to handle these cases, not reject them.
- **One AST, all sub-languages.** The HTML parser also parses the **CSS and JavaScript embedded inside the HTML** (`<script>`, `<style>`, `onclick`, `style` attributes…) and exposes everything as a **single unified AST**. This makes it practical to **stream over the nodes** of a full web page — HTML, CSS and JS — without juggling three separate parsers and three separate trees.
- **Degraded parsing — never throw.** When the parser encounters an unrecognizable combination, it doesn't stop and it doesn't throw: it emits an **error node** into the AST and **resumes parsing**, so you still get the maximum number of recognizable nodes from a broken or partially-malformed source. Perfect for linting, static analysis, or any pipeline that must keep going on imperfect inputs.
- **Exact source locations.** Every AST node carries its precise location in the source (offsets, lines, columns). Critical for diagnostics, refactoring tools, code-intel features, and any downstream consumer that needs to point back at the original text.
- **Comments are first-class.** Comments are parsed in every supported language and kept with their own source locations. A dedicated API lets you look them up **relative to any AST node** (leading, trailing, inside…), so you never lose the connection between code and its documentation — essential for doc generation, lint rules that read pragmas, and AI tools that rely on intent expressed in comments.
- **Simple API.** Parsing a source is a one-liner; the resulting AST is a plain typed tree you can walk, query, or stream over. Easy to plug into existing JVM tooling.
- **JSON serialization.** Every AST node is fully serializable and deserializable to JSON out of the box (via Jackson). You can persist a parsed tree, send it over the wire, or reload it later without re-parsing the original source.
- **AI-friendly.** A clean, typed, located AST gives an LLM or an analysis agent a much stronger signal than raw source text. The framework is designed to be a building block for **AI-driven code understanding** — improving analyses, refactoring suggestions, and overall code comprehension.
- **Built for static analysis.** Together the parsers make a practical toolkit for **static analysis of web applications** end-to-end: HTML structure, embedded scripts, stylesheets, and standalone JS/CSS/XML files — all parsed into the same shape.
- **A parser-combinator library underneath.** The framework also ships its own parser combinator library (`yari-parsec`), which is what makes the degraded-parse behavior composable across every language: error recovery is a first-class primitive of the combinators, not an afterthought bolted onto each parser.
- **Heavily tested.** Each module ships with an extensive test suite covering as many cases as possible — and it keeps growing as new edge cases surface. Contributions of untested cases are welcome.

## Quick Start

### Parse a full HTML page — unified AST

```java
String source = """
    <html>
      <head>
        <style>.btn { color: red; }</style>
      </head>
      <body>
        <!-- main action -->
        <script>
          function greet(name) { return "Hello " + name; }
        </script>
        <button style="font-size:14px" onclick="greet('world')">Go</button>
      </body>
    </html>
    """;

Html html = HtmlParser.parse(source, HtmlConfig.defaulConfig());
```

### Walk the unified tree — HTML, CSS, and JS in one pass

```java
html.walkChildren(handler -> {
    switch (handler.node()) {
        case Tag tag ->
            System.out.println("tag: " + tag.getHead().getName());
        case ScriptTag script -> {
            Javascript js = script.getScript().getJavascript();
            System.out.println("script: " + js.getNodes().size() + " statements");
        }
        case StyleTag style -> {
            Css css = style.getStyle().getCss();
            System.out.println("style: " + css.getNodes().size() + " rules");
        }
        default -> {}
    }
});
```

### Source locations — every node knows where it lives

```java
AstResult<Javascript> result = JavascriptParser.parseUnit(source);

result.getNode().astStream()
      .filter(n -> n instanceof FunctionDeclaration)
      .forEach(n -> {
          SourceLocation loc = n.getSourceLocation();
          System.out.printf("function line %d → %d%n",
              loc.start().line(), loc.end().line());
          System.out.println(result.substring(loc));
      });
```

### Comments — preserved with location, queryable per node

```java
AstResult<Javascript> result = JavascriptParser.parseUnit(source);
Javascript js = result.getNode();

// All comments in the file
List<AstComment> all = js.astComments();

// Comments immediately before each top-level node
js.getNodes().forEach(node ->
    js.astCommentsOf(node, AstUnit.Position.before)
      .forEach(c -> System.out.println("before " + node + ": " + c)));
```

### JSON serialization — serialize and deserialize any AST node

```java
ObjectMapper mapper = new ObjectMapper();

// Serialize
AstResult<Javascript> result = JavascriptParser.parseUnit(source);
String json = mapper.writeValueAsString(result.getNode());

// Deserialize
Javascript restored = mapper.readValue(json, Javascript.class);
```

### Degraded parsing — broken input still produces a usable AST

```java
// Unclosed tag — no exception, an error node is inserted and parsing continues
Xml xml = XmlParser.parse("""
    <root>
        <item>ok</item>
        <broken
        <item>still parsed</item>
    </root>
    """, XmlConfig.builder().acceptUnclosedTag(true).build());

xml.astStream()
   .filter(n -> n instanceof ErrorNode)
   .forEach(n -> System.out.println("error at " + n.getSourceLocation()));
```
